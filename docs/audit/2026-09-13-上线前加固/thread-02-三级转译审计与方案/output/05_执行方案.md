# 05 · 三级转译执行方案（S5）

> [来源: T2三级转译审计 @ 2026-09-13] ｜ 前置：01（口径）/02（实证）/03（判定）/04（抽测）｜ 状态：待主控+用户裁决

## 一、架构决策

### 决策 A（推荐）：确定性词库 + LLM 受限生成的混合转译管线

**数据层**：新增「原型转译库」（区别于现有 1180 条术语词典，后者保留为 L0 术语层）：

```
PrototypeEntry = {
  archetype_key: 'bazi-shishen-qisha-001',   // {system}-{category}-{term}-{variant}，白皮书 2.3 契约
  system: 'bazi',                             // 体系
  l1_anchor: { book, chapter, page, quote, edition },  // 2.1-01：卷/页/原文/版本锁定
  l2_commentary: { author, work, publisher, year, page, text },  // 2.1-02
  l3_plain: string,                           // ≤200 字中性白话，2.1-03 五规则
  l4_matrix: { career, wealth, love, health, ... },  // 2.1-04 领域投射
  l5_scenes: { [audience_tag]: string },      // 2.1-04 人群场景
  dict_version: string,                       // 2.1-09
  review: { linguist_sign, legal_sign, psychologist_sign, date },  // 2.1-10/17/21
}
```

**管线层**（三段式）：
1. **引擎段（确定性）**：排盘结果 → 原型识别（十神组合/主星落宫/牌义等）→ 按 archetype_key 直查词库，输出 L1 锚定 + L3 白话——**这部分不经过 LLM，天然 100% 准确可复现**。
2. **受限生成段（LLM）**：L5 场景文案与个性化衔接由 LLM 生成，但前提全面收紧：temperature=0（2.1-06/2.2-01）、system prompt 注入合规铁律（禁用词表/趋势化表达/禁医疗金融断言）、用户敏感提问先经主题改写器（把「能不能回本」改写为「财运趋势如何」）、输出经禁用词过滤器 + 语义熔断器（检出 L3 未提及的具体病症/金额/事件即重写）。
3. **版本化段**：每份报告 JSON 写入 `engine_version + dict_version + model_version` 三元组（2.1-09）。

**理由**：①468 红线 24 项的可验收性几乎全部要求「确定性可查」（卷页溯源/相似度阈值/覆盖率 100%），纯 LLM 路线在架构上无法 pass；②抽测证明引擎证据链已 100% 结构化（53/53），只缺「原型→文案」的最后一公里，成本集中在数据不在算法；③白皮书 2.3 早已预设此架构（archetype_key 对接），A 是「回归原计划」而非新发明。

**成本**：主要工作量在 800 条原型 × L1/L2/L3/L4/L5 数据生产（含人工审核），AI 可辅助起草 L3/L5 但 L1 出处必须人工核验。详见工作量评估。

### 决策 B：正式降级为「LLM+约束」，修订红线状态

保留现有链路，仅补齐：temperature=0、合规 system prompt、敏感问题改写、输出禁用词过滤、兜底回复。24 项中约 6-8 项可升级 pass（06/16/18/19/08 部分等），L1/L2/L4/L5/覆盖率/签字等 10+ 项申请修订为「na 或重定义」。

**代价**：①内容质量上限锁死在 LLM 平均水平，术语漂移不可控（抽测评分 F 的忠实度/术语一致性无解）；②出海多语言（T3）在无锚定文本的前提下翻译质量不可控——**T3 的「100% 准确」目标在决策 B 下无法达成**；③修订 468 红线体系动摇 V5.0 审计标准的权威性，对外宣称「古籍锚定」的卖点消失。

**结论：推荐 A**。若排期紧张，可 A/B 混合过渡：先做 A 中的 M3 运行时约束（2 周内可见效，立即收窄风险敞口），词库按体系分批上线（先八字后紫微）。

## 三、依赖与接口

1. **依赖 T1（排盘准确性）**：原型识别建立在排盘正确之上——M3 的 archetype_key 全链打通须以 T1 十神/格局/星曜审计通过为前提。M1 运行时约束**不依赖 T1，可立即启动**。
2. **接口约定给 T3（多语言）**：
   - **术语键 = archetype_key**（`{system}-{category}-{term}-{variant}`），T3 术语表按此键建 7 语言映射；
   - **翻译源文本 = L3 白话**（确定性、≤200 字、无文言），L5 场景文案为第二优先级；
   - 脱敏表（2.1-08）由本线程 M1 产出中文版，T3 按语言扩展并回写至同一配置文件（`src/data/sanitizer.ts` 建议路径）；
   - 吉凶方向校验（2.1-20）在 T3 完成首批 7 语言映射后联合演练。
3. **与 T4 共享**：禁用词表、黄金样例库（本线程 53 条样本 JSON 可作为初始黄金样例）、评测集规范归 T4 归口（README 硬规则 3）。

## 四、不做（边界）

- 不做多语言翻译实现（T3）；不终裁红线状态（主控+用户）；不改线上部署与 sw 版本（主控权）；L1 古籍原文的大规模录入不在本方案内做自动化 OCR（法律与准确性风险，人工核验路径已在 M2）。

## 五、风险

| 风险 | 缓解 |
|---|---|
| 800 原型 L1 出处人工核验慢（古籍版本多样） | 先做「高频 200 原型」覆盖 Top 流量的 80%，其余分批；版本锁定规则在 M2 schema 里强制 |
| temperature=0 后文案多样性下降 | 多样性由 L5 场景矩阵（人群×领域）提供结构化差异，不靠随机性 |
| 词库更新后历史报告渲染漂移 | 三元组版本化（M1）+ 历史报告按生成时版本渲染规则一并落地 |
| 敏感提问改写器误杀正常问题 | 改写仅收敛句式不改语义；保留原问题附注；灰度一周对比（git 可回滚） |
