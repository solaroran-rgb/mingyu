## 二、任务目标

1. **现状排查（a）**：给出三级转译的规则代码/公式/脚本的**部署阶段判定**（原计划 vs 实际 vs 质量分级），全部有代码证据，不凭印象。
2. **方案制定（b）**：输出深度审计报告 + **下一步执行方案**（含架构决策、里程碑、验收标准、工作量评估）。

### S5 方案制定（1.5 天）
- 输出 `output\05_执行方案.md`，必须包含：
  1. **架构决策**：决策 A 落地确定性 L1–L5 转译管线（数据结构：`{archetype_key, L1出处, L2注疏, L3白话, L5场景, 版本, 体系}`；词库分级扩充；引擎直接输出 L1 锚定 + L3 白话，L5 由 prompt 受限生成）vs 决策 B 正式降级为「LLM+约束」并修订红线状态。**推荐 A（混合：确定性词库 + LLM 受限生成）**，给出理由与成本。
  2. **里程碑**：M1 数据模型与词库升级（800→分支转译库）→ M2 引擎输出对接（archetype_key 全链打通）→ M3 熔断器落地（Temperature=0/版本冻结/注入防护）→ M4 红线 2.1 逐项 pass 申报。
  3. **工作量评估**（人日）+ 依赖（T1 的排盘准确性、T3 的多语言术语表）。
- 与 T3 的接口约定：转译管线输出的结构化文案是 T3 多语言翻译的输入，术语键格式须与 T3 术语表一致（见 README 共享规范）。
