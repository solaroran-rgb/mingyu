## 一、现状结论（审计实证）

1. **网站当前不具备任何排盘内容多语言能力**：排盘引擎输出 → 提示词模板 → API 请求体 → LLM 网关全链路 grep 语言参数 **0 命中**（实测）；system prompt 中文硬编码（`src/lib/ai/proxy.ts:51`）且 temperature=0.7 零约束透传（与 T2 抽测互证）。
2. **无回译/翻译校验机制**；lexicon 1180 条无译名字段且仅词库页消费；i18n 仅 UI 静态词条（约 136 键×7，76 条母语复核未做）。共 9 断点（BP1–BP9），详见 01。
3. 多语言是白皮书规划态（§3.6 L0–L7 / 800 条 / archetype_key），代码零实现——**「排盘结果直接翻译」与「三次转译的多语言」目前都是 0%**，这不是质量差，是机制不存在（与 T2「转译不是做得差而是没被做」同构）。

## 六、依赖与风险（Top 5）

1. **T2 M1 协同**：运行时约束与语言分支同在 proxy.ts/prompt-builders 施工，需主控合并排期（避免双改冲突）。
2. **引擎输出键化（BP1）**：动 core 21 体系输出结构，改键须四线程会签（T4「键即契约」）；这是全管线最大前置。
3. **th/vi 稳定性**：试运行已实证 th 音译错译风险 → 上线策略：th 术语层先 untranslated 降级或仅白名单术语，母语复核后放开。
4. **母语复核人员**（6 语言）：复核表已就绪，人员到位即开复核；结果返回后按 G4 处置。
5. **KV 缓存**：术语表版本号必须进缓存 key，防旧译文残留（04 §六.3）。
