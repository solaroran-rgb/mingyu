## 一、结论（TL;DR）

**网站当前不具备任何排盘内容的多语言能力，多语言仅存在于 UI 静态词条一层。**

1. 「排盘结果→解读文案」全链路（排盘引擎输出 → 提示词模板 → API 请求体 → LLM 网关）**实测 0 处语言参数命中**（grep `\b(lang|locale|language)\b` 于 `packages/core/src/prompt` + `src/lib/public-api` + `src/lib/ai` = **0 命中**，2026-09-13 05:00 实测复核）。
2. LLM 网关 system prompt 中文硬编码（`src/lib/ai/proxy.ts:51`），输出语言完全靠 LLM 跟随中文提示词，无受限翻译模式。
3. **无回译、无翻译校验机制**：全仓 grep `translate|回译` 仅命中 Three.js 几何变换 `cone.translate(...)`（`src/lib/city/meshBuilder.ts:152`），与文本翻译无关。
4. 术语词典 lexicon 1180 条**无任何语言译名字段**，且仅被词库搜索页消费，未进入排盘/提示词链路。
5. i18n 词典 7 语言同构（约 136 叶子键 × 7），仅覆盖 UI 静态词条；**排盘结构化数据（干支/星曜/宫位/神煞）与解读文案 0 键覆盖**。
6. 共 9 个断点（见第六节），其中 BP1–BP5 为链路级断点（翻译机制缺失），BP6–BP9 为资产级缺陷（术语表/i18n 质量）。

## 六、断点清单（每条：位置 / 证据 / 影响 / 修复方向）

### BP1 · L0 结构化字段硬编码中文，无术语键化 ❌
- **位置与证据**：
  - `packages/core/src/ganzhi/data.ts:9` `export const HEAVENLY_STEMS = ['甲','乙','丙','丁','戊','己','庚','辛','壬','癸'] as const;`（:13-26 地支、:30 起生肖同为中文）
  - `packages/core/src/bazi/baziShenShaData.ts:4` 神煞名/分类全中文典（数百条：`天乙贵人: '贵人'...`）
  - `packages/core/src/shensha/index.ts:30` `ShenshaResult { id: string; name: string; ... }` —— `name` 即中文神煞名
  - `packages/core/src/ziwei/iztro/build-analysis-payload/helpers/builders.ts:48` `body_palace_name: bodyPalace?.name`（iztro 中文星曜/宫位直出）；`:238` `` tags.push(`自化${mutagen}`) ``
- **影响**：L0 是「确定性字段 100% 机器断言」的对象，但当前输出连翻译承载键（archetype_key）都不存在，前端只能渲染中文。
- **修复方向**：排盘输出结构增加 `archetype_key` 字段（命名规范与 T2 对齐），前端按 locale 查 7 语言术语表渲染；中文 value 保留为兜底。

### BP2 · 提示词模板纯中文，无语言参数、无语言分支 ❌
- **位置与证据**：`packages/core/src/prompt/types.ts:10-15` `PromptBuildOptions { currentTime?: Date; question?: string }` —— 唯一选项接口，**无 language 字段**；`public-api.ts:378-386` `buildBaziPromptForResult(params{result,question?,topic?,mode?,school?...})` 无 lang；`bazi.ts:41` `TOPIC_LABELS = { general:'通用', career:'事业', ... }`；grep 实测三目录 0 命中。
- **影响**：L1/L3/L5 全部文案生成无多语言入口。
- **修复方向**：`PromptBuildOptions` 增加 `language?: LocaleCode`，模板按语言分支 + 术语表注入（详见第八节 S4 推荐）。

### BP3 · API 层无语言参数，前端无通道可传 ❌
- **位置与证据**：`functions/api/v1/[[path]].ts:12-20` catch-all → `handler.ts:1586-1587`；ziwei/calculate 请求体字段全集 `handler.ts:2661-2710`（birthDate/timeIndex/…/promptScope），prompt 端点 `:2731-2738`（question/promptTopic/promptMode/school）；grep `handler.ts` 语言参数 **0 命中**。
- **影响**：即使前端想传语言，接口也无承载字段。
- **修复方向**：请求体加 `lang` 字段并贯通至 PromptBuildOptions；OpenAPI 文档（handler.ts:397 起）同步登记。

### BP4 · LLM 网关无语言控制，无受限翻译模式 ❌
- **位置与证据**：`src/lib/ai/proxy.ts:51/:53` system prompt 中文硬编码；`:64` 请求体仅 `{prompt, messages, aiConfig}`；`:136-148` 上游参数 `model/stream/max_tokens:4096/temperature:0.7`，默认上游 `api.deepseek.com` + `deepseek-chat`（:15-16）；SSE 原样透传（:168-257）。
- **影响**：输出语言完全依赖 LLM 跟随中文提示词；temperature=0.7 不满足「确定性/受限翻译」要求。
- **修复方向**：system prompt 按语言选择；翻译类请求走独立参数档（temperature=0、术语表注入、禁改数值/方向约束）。

### BP5 · 无回译、无翻译校验机制 ❌
- **位置与证据**：全仓 grep `translate|回译` 仅命中 `src/lib/city/meshBuilder.ts:152`（Three.js `cone.translate(...)`，几何变换，与文本无关）。
- **影响**：翻译质量验收层完全空白，S5 校验体系（回译一致率/母语复核/门禁）需从零建设。
- **修复方向**：S5 新建回译脚本（复用 /api/v1/ai/analyze 或 8877 LLM），门禁纳入 T4 全量回归。

### BP6 · 术语词典无译名字段、未入链路 ⚠️
- **位置与证据**：`lexicon.ts:42-48` 五字段 `{term, pinyin, category, definition, source}`；唯一消费方 `src/pages/LexiconPage.tsx:5`。
- **影响**：S3 的 7 语言术语表**不能**复用 LexiconEntry 结构，需新建含 7 语言译名 + archetype_key + 状态字段的表；且词库术语与排盘输出术语之间无键值关联。
- **修复方向**：新建 `archetype_key → {zh, en, es, ja, ko, th, vi, pinyin, source, status}` 结构（对齐 T2 术语键）；词源 = lexicon 1180 条 + 排盘输出实际术语全集（天干地支/星曜/神煞/64 卦/十二宫等）。

### BP7 · i18n 词典与内容层脱节 ⚠️
- **位置与证据**：`zh-CN.ts:1-164` 顶层键全集无排盘/解读类键；`en.ts:1` 类型锁 `Dict` 同构。
- **影响**：内容层 0 键覆盖；好在 7 语言同构类型锁是现成的防漏译保障，扩键即可继承。
- **修复方向**：内容层译文走独立术语表/翻译产物，不塞 UI 词典（避免 136 键词典膨胀为数千键）；仅短 UI 化的 L0 标签可进词典。

### BP8 · 面向用户错误文案中文直出 ⚠️
- **位置与证据**：引擎异常 `packages/core/src/ganzhi/relations.ts:506` `` throw new Error(`驿马数据缺失：${yearBranch}`) ``；API 错误 `src/lib/ai/proxy.ts:72/:75/:113/:124` message 全中文（如 `'请求体必须是合法 JSON。'`）。
- **影响**：非中文用户在异常路径必然看到中文报错，破坏出海体验。
- **修复方向**：API 错误改为「错误码 + 参数」结构，前端按 locale 映射文案；引擎异常消息不直接透出给用户。

### BP9 · UI i18n 自身未达验收（既有债）⚠️
- **位置与证据**：母语复核清单 76 条 0 完成；问题类型见 A2。
- **影响**：即使内容层翻译落地，「7 语言 100% 准确」在 UI 层也有 76 条未收口。
- **修复方向**：与内容层译文共用母语复核渠道（S5 复核表合并交付）。
