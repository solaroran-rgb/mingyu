## 一、架构总览（决策 A 在 T3 的落法）

```
[前端] locale 切换（i18n 既有机制，UI 词条轨，不新增职责）
   │
   ├─① L0 结构化渲染（确定性轨，不过 LLM）
   │    Board 组件（BaziChartBoard/ZiweiBoard/ZiweiTraditionalBoard/QizhengBoard/AstrolabeBoard）
   │    └─ 以引擎输出的 archetype_key 查 terms-7lang.ts（构建期由 7lang-terms.csv 生成）
   │         ├─ 命中 → 渲染目标语言标签（G1 可断言）
   │         └─ 缺失 → 显示 archetype_key 原文 + 「未翻译」徽标（G5 禁 zh 兜底）
   │
   └─② 文案生成/翻译（受限生成轨，走 LLM）
        POST /api/v1/ai/analyze 请求体新增 lang 字段（BP3 修复）
          ↓
        handler.ts：lang 白名单校验（7 locale，非法 → 结构化 400，BP8 修复）
          ↓
        prompt-builders（BP2 修复）：PromptBuildOptions 新增 language
          ├─ 模板骨架语言分支：L1/L3/L5 各一套×7 的「结构化指令模板」（键控槽位，非自由文本）
          ├─ 术语注入：按 prompt 涉及体系加载 archetype_key 子表（tier1 优先）
          └─ 受限生成约束（写入 system/user 指令，T2 决策 A 的运行时约束）：
              temperature=0（BP4 修复）、数值/干支/星曜/吉凶方向禁改、
              术语只准用注入表、输出包裹 <translated> 标记便于机检
          ↓
        proxy.ts：system prompt 按 language 选择（BP4 修复）
          ↓
        响应门禁预检（服务端，新增 gate 模块）：
          G2 术语命中扫描（译文中的术语词元必须能反查 archetype_key）
          G3 回译抽检（按 05_backtranslate_check.py 同源逻辑）
          ├─ 通过 → SSE 正常回传
          └─ 失败 → 该字段标 untranslated，前端显示源文+徽标
```

**两轨分工**（对齐 T4 规范）：UI 静态词条继续走 `src/i18n/locales/*`（134×7，含 76 条待复核）；排盘内容（L0 标签 + L1/L3/L5 文案）一律走本管线 + 术语表，**两轨不混**。

## 二、管线位置推荐与理由

**推荐：后端 prompt-builders 加语言分支（主）+ 前端 L0 查表渲染（辅），API lang 字段贯通。**

| 备选 | 结论 | 理由 |
|---|---|---|
| **A. 后端 PromptBuildOptions.language（推荐）** | ✅ | ①改动面最小：单点类型 + 请求体一字段 + system prompt 分支，全部落在审计已定位的文件（types.ts/public-api.ts/proxy.ts/handler.ts）；②约束与门禁在服务端收口，前端无法绕过 G2/G3；③同 lang 产物可 KV 缓存，成本可控；④与 T2 决策 A 的运行时约束同一落点（proxy.ts:140 temperature 透传问题一并修） |
| B. 前端对 LLM 输出做机翻 | ❌ | 术语约束无法保证（机翻器不认 archetype_key）、门禁形同虚设、暴露实现细节 |
| C. 每语言独立模板文件（17 文件×7） | ❌ | 模板爆炸、维护漂移；改为「键控槽位 + 语言包」结构 |

## 三、每层实现方式

| 层 | 输入 | 机制 | 门禁 | 关键修复 |
|---|---|---|---|---|
| **L0** | 排盘结构化输出（含 archetype_key，依赖引擎侧键化） | 前端查表渲染，纯静态、零 LLM | G1（黄金样例×7 断言）+ G5 | BP1（引擎输出加键）、BP7（渲染层） |
| **L1** | 古籍锚定段（T2 词库锚定产物） | 术语查表强制替换 + LLM 受限翻译 + 典籍锚点原样保留 | G2/G3/G4 + 锚点逐条可溯源（溯源缺失判 FAIL） | BP2/BP4/BP6 |
| **L3** | 白话解读文案 | 术语查表 + LLM 受限翻译 | G2/G3/G4 | 同上 |
| **L5** | 场景文案 | 同 L3 + 场景模板字段完整性校验 | G2/G3/G4 | 同上 |

**LLM 受限生成调用规范**（对齐 T2 抽测结论「temperature=0.7 零约束透传」）：
- temperature=0、top_p≤0.1；术语表以 JSON 注入 user 指令；输出 JSON 包裹 `<translated lang="vi">…</translated>`；
- 术语未命中处理：**先补词库**（T4 规范：禁 LLM 直译关键术语），管线内出现未登记术语 → G2 FAIL → untranslated。

## 四、失败降级策略（口径第五节落地）

| 故障 | 降级动作 | 永不发生的事 |
|---|---|---|
| L0 键缺失 | 显示 archetype_key + 未翻译徽标 + 上报计数 | 静默渲染中文 |
| LLM 超时/失败/输出不带标记 | 该字段 untranslated（显示源文） | 用非受限模式重试蒙混 |
| G2 术语未命中 | 该字段 untranslated + 词库缺口工单 | LLM 现场发明译法 |
| G3 回译一致率 <98%（按语言） | 该语言该层文案整体下线为 untranslated | 局部修补后带病上线 |
| G4 母语硬伤 | 对应条目回滚 untranslated，进复核队列 | 以均值豁免硬伤 |

## 六、风险

1. **引擎输出键化（BP1）是最大前置**：涉及 core 21 体系输出结构，须与 T2 词库锚定共用同一套 archetype_key（T4 规范「键即契约」），改键需四线程会签。
2. **Qwen/DeepSeek 对 th/vi 的术语稳定性未验证**：M3 门禁预检会暴露，届时按语言分列一致率，必要时该语言先降级 untranslated 上线。
3. **KV 缓存失效风暴**：术语表版本号必须进缓存 key（对齐 T4 快照机制），否则更新术语表后旧译文残留。
