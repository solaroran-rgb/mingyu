## 一、任务背景

用户判定「后端还不坚固」。排盘是产品根基，必须逐板块审计规则/公式/代码逻辑，并与各板块排名前 5 的权威网站做同数据比对，先保证所有排盘结论准确，才能谈转译与多语言。已有 `_audit_20260912\` 的 10 组八字对勘基础，但**仅覆盖八字、只落盘未判定**，且暴露 **ziwei 全 503、晚子时/立春 Worker Error 1102**。

## 二、任务目标

1. 21 体系（见范围）逐一输出《排盘规则审计表》：规则来源（古籍/公式/算法）→ 代码位置 → 输入契约 → 输出契约 → 边界处理。
2. 每体系与**该板块排名前 5 的网站**同数据比对，输出《比对测试报告》：逐字段一致/差异明细 + 差异归因（口径差异 vs 真 bug）。
3. 修复确认为 bug 的排盘逻辑并回归；**目标：所有排盘结果达到准确结论（字段一致率 100%，或全部差异归因闭环、无未解 bug）**。

## 三、任务范围

**21 体系端点清单**（以 `packages/core/src/` 与 `src/lib/public-api/` 实际路由为准核对）：
- 命理：bazi（八字）、ziwei（紫微）、qizheng（七政四余）、taiyi（太乙）、huangji-jingshi（皇极经世）、wuyun-liuqi（五运六气）、zodiac（生肖）、vedic（吠陀）
- 占卜：liuyao（六爻）、meihua（梅花）、qimen（奇门）、liuren（大六壬）、xiaoliuren（小六壬）、jinkoujue（金口诀）、tarot（塔罗 15 牌阵）、lenormand（雷诺曼）、ssgw（三山国王灵签）、almanac（黄历择日）
- 星盘/风水：astrolabe（西洋星盘+合盘）、xuan_kong（玄空）、ba_zhai（八宅）、residential_fengshui（住宅风水）

## 四、执行步骤

### S1 端点与实现盘点（0.5 天）
- 从 `src/lib/public-api/` 路由清单 → `packages/core/src/` 逐一映射「端点 → 实现文件 → 测试文件」，产出《体系-代码-测试映射表》，缺失映射的标 ⚠️。

### S2 规则审计（每体系 0.5–1 天，并行）
- 每体系填写审计表：规则来源（如八字=子平法+《渊海子平》，公式=天干地支历算，星历=Meeus《天文算法》第 28 章等）→ 代码实现位置 → 输入契约（zod schema）→ 输出契约（字段清单）→ 边界处理（子时口径/节气交接/闰月/DST）。
- 输出：`output\规则审计表_<体系>.md`（或合并为 `规则审计总表.md` + 分表目录）。

### S3 选定每体系 top5 比对站（0.5 天，豆包在线核验）
- 每体系选 5 个公认权威站（示例：八字=问真八字/元亨利贞/文墨天机；紫微=文墨天机/紫微斗数排盘网；占卜=各体系专业站/典籍推演），**在线核验可达性 + 是否支持同参数输入**；不可达/需登录的记入备注并换替补。
- 产出：`output\比对站清单.md`（站名/URL/支持参数/口径说明，如是否默认真太阳时）。

### S4 黄金样例集建设（与 S3 并行）
- 复用 `_audit_20260912\results\10_*` 10 组输入，扩展至**每体系 ≥10 组**（覆盖边界），统一存 `output\golden-cases\<体系>\<case-id>.json`（输入模板 + 期望字段声明）。
- 样例来源：典籍推演、权威站导出、人工推演；每条标注来源与可信度。

### S5 比对脚本与执行（核心重活，2–3 天）
- 扩展 `_audit_20260912\cross_check.py` / `run_temposoul.py` → 新增 `compare_vs_sites.py`：
  - 同数据请求引擎 + 各站（API 可用则 API；否则抓页面解析，抓取受限则记录「该站仅人工比对」）；
  - 输出逐字段 JSON diff：`{体系, case, 字段, 引擎值, 网站值, 一致?, 差异类型}`。
- 执行全部 21 体系 × 10 组 × 5 站；**每站比对记录 URL 与抓取时间**（可追溯）。
- ⚠️ 遇 503/Error 1102：记录输入与堆栈，**不修**（归 T4），但列入报告「阻塞清单」。

### S6 差异归因与修复（2 天）
- 差异分类：A 真 bug（引擎错）→ 修复 + 单测；B 口径差异（真太阳时/早晚子时/流派）→ 文档化并确认线上默认口径；C 比对站错误 → 记录；D 边界争议（古籍歧义）→ 标「需专家裁决」。
- 每类差异必须闭环：修复 / 文档化 / 标争议，不允许悬空。

### S7 回归与报告（1 天）
- 全量测试：`test:core` / `test:api` / `test:prompt` 串行全绿（基线 core 1539 / api 107 / prompt 229）。
- 输出：`output\比对测试报告_<体系>.md`（每体系）+ `output\审计总结.md` + 修复 commit 清单。
