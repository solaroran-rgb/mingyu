# 红线 1.1-06 · 国际夏令时（IANA tzdata）—— P1 证据

- 线程：thread/redline-p1-evidence ｜ 日期：2026-09-13
- 三态判定：🟡 有实现缺证据 → **补证据后 pass**

## 红线要求
timeZoneId 应按 IANA tzdata 历史规则解析夏令时跳变，而非固定偏移。

## 实现位置 / 入口
- `packages/core/src/calendar/historical-timezone.ts`（`resolveHistoricalTimezone({..., timeZoneId})`）
- `packages/core/src/calendar/civil-time.ts`（民用时间统一入口 `resolveCivilTime`）
- 中国境内另有 `china-dst.ts` 固定为不实行 DST。
- 底层依赖运行时 ICU / IANA tzdata（Node `Intl`），与 `tests/utc-tt-samoa.test.ts` 同入口。

## 验证方式
新增自动化测试：`tests/1.1-06-iana-tzdata.test.ts`（4 用例，全部通过）：
1. 纽约 1 月 = UTC-5（EST）、7 月 = UTC-4（EDT），夏令时跳变 +1h 方向正确；
2. 伦敦 1 月 = UTC+0、7 月 = UTC+1（BST）；
3. 亚洲/上海 冬夏均为 UTC+8，全年无跳变；
4. 纽约夏令时起点 2024-03-10 中午本地 → UTC 折算 `2024-03-10T16:00:00Z`（= -4）。

## 结论与残留缺口
- IANA tzdata 夏令时解析**已满足**，冬令时/夏令时/不实行 DST 三类均有回归钉住。
- 残留：gaps 建议的“CI 内 tzdata 版本核对 + 48h 同步检查脚本”未单独建脚本；当前由运行时 Node ICU 承担，建议后续在 CI 打印 `process.versions` 与 tz 数据版本作观测项。
