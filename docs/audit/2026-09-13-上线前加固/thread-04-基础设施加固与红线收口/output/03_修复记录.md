## Commit 98cad2a · fix(core,api): 时区冲突/回拨歧义/跳时缺口返回 400 结构化错误，不再 500

### 改了什么

| 文件 | 改动 |
|---|---|
| `packages/core/src/calendar/civil-time.ts` | `resolveCivilTime` 三处原生 throw → `MingyuCoreError`（validation）：`AMBIGUOUS_LOCAL_TIME`（回拨歧义）/`TIMEZONE_OFFSET_CONFLICT`（偏移冲突）/`TIMEZONE_REQUIRED`（缺时区）。消息文本不变 |
| `packages/core/src/calendar/historical-timezone.ts` | 四处原生 throw → `MingyuCoreError`（validation）：`INVALID_TIMEZONE_ID`×2 / `NONEXISTENT_LOCAL_TIME`×2（含萨摩亚跳日）。消息文本不变 |
| `src/lib/public-api/handler.ts` | 新增 `isMingyuCoreError()` 判别（instanceof + `name==='MingyuCoreError'` 哨兵），替换 `handleError` 与太阳光照 rethrow 守卫两处裸 `instanceof`。原因：测试环境 `@core/*`→src 与 barrel→dist 双类副本使 `instanceof` 失效（线上单 bundle 无此问题，但哨兵写法对两种环境都稳健） |
| `tests/civil-time.test.ts` | 新增三场景 MingyuCoreError 类别/码断言（gap/ambiguous/conflict） |
| `tests/public-api.test.ts` | 新增 API 级回归「时区冲突与夏令时跳时应返回 400 而非 500」（两个线上 100% 复现的 500 输入） |

### 为什么改（证据）

- 线上实证（`01_503复现记录.md`）：`timezone=8 + timeZoneId=America/New_York` → 500 INTERNAL_ERROR（4/4）；`2024-03-10 02:30 America/New_York`（夏令时跳时缺口）→ 500。
- 根因：`handleError` 只识别 `ApiError`/`MingyuCoreError`，core 校验层抛原生 `Error` 落入兜底 500；OpenAPI schema 承诺冲突时应 400 拒绝。
- 效果：此类用户输入错误现在返回 `400 {ok:false, error:{code:'TIMEZONE_OFFSET_CONFLICT'|'NONEXISTENT_LOCAL_TIME'|..., message}}`，满足证据型输出契约。
